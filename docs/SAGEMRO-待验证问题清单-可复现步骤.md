| 项 | 内容 |

## B 档 · 需要多账号或特定数据

### B1 · 知识沉淀环断开 ⭐ 最该试的一条

这是整个审计里**最高优先级的修复项**，值得花时间完整走一遍。

| 项 | 内容 |
| --- | --- |
| 环境 | 工程师账号 + 客户账号 + admin 账号 |
| 步骤 | ① 工程师完成一张工单并提交服务报告<br>② 客户在 ai.sagemro.com 对该工单**评分**并验收<br>③ admin →「知识候选」页，看有没有自动产生候选<br>④ 若有，走审核流程到「通过」<br>⑤ admin →「知识库」，找到刚产生的条目，看它的**状态**<br>⑥ 尝试把它发布上线 |
| 预期现象 | 候选可能产生；审核通过后新条目状态是 **`draft`**；且在知识库页**无法发布**（接口返回 409） |
| 正确现象 | 审核通过后应能发布，并进入 AI 检索库 |
| 技术原因 | `index.js:17495` 写入硬编码 `'draft'`；`index.js:12895-12897` 对候选来源条目发布返回 409 |
| 确认后意义 | P0-1。**确认了就意味着"工程师沉淀的经验永远进不了 AI"**，飞轮的知识环物理上闭合不了 |
| 注意 | 第 ② 步是必要条件——候选产生要求客户评分 + `customer_confirmed_at` |

### B2 · 检索串档（问 3000W 拿到 3000S）

| 项 | 内容 |
| --- | --- |
| 前提 | KB 里同时有 3000W 与 3000S 机型的已发布条目 |
| 步骤 | 客户账号问：`3000W 碳钢 16mm 切割参数` |
| 预期现象 | AI 可能引用 3000S 的数据（实跑 122 行真实数据时 top-5 全是 3000S） |
| 技术原因 | `CAST('3000W') = CAST('3000S') = 3000`，精确型号加权失效（`index.js:1521`） |
| 确认后意义 | P0-3。用错机型的参数回答客户是"专业可信"的反面 |
| 注意 | 现在 KB 多为 draft，可能先需要发布对应条目才能试 |

### B5 · fixed_date 分期收款死锁 ⚠️ 需要走完整流程

| 项 | 内容 |
| --- | --- |
| 步骤 | 商务报价时选择 **`fixed_date`（固定日期）分期** → Admin 审核通过 → 客户确认报价 → 发起收款 |
| 预期现象 | 发起收款失败，提示「当前分期状态不允许发起收款」 |
| 技术原因 | 报价确认后 `site_timezone` 永久不可写（`16320-16322`），而 fixed_date 分支需要它（`20358-20361`）→ 永远收不到 → 工单永远不能 `completed` |
| 确认后意义 | P0-7。**这是运营级死锁**，规模化后每个 fixed_date 分期的单都会卡住 |
| 注意 | 只能 Admin 人工放行绕开；建议用测试工单做 |
