# SEO 操作手册

本手册记录当前已实现的公开 SEO 基础和日常运营规则。选题、关键词和发布状态以 [关键词映射](../research/seo-keyword-map.md) 及前端公开路由清单为准；不要把草稿、私有路径或直达但禁止索引的工具当作自然搜索资产。

---

## 一、当前技术事实

### 1.1 公开页面如何生成

- `frontend/src/data/publicSeoRoutes.js` 是双语公开路由的唯一清单。它只读取已发布的服务页、诊断指南和可索引工具；公开工具当前为材料重量、激光切割成本、V 槽与折弯展开三个记录。
- `npm run build` 先执行 Vite，再执行 `frontend/scripts/buildPublicPages.mjs`。后者从同一清单写出每条公开路径的静态 `index.html`、`sitemap.xml`、`robots.txt`、`llms.txt`、尾斜杠重定向和 `404.html`。
- 静态 HTML 在客户端 JavaScript 前提供标题、描述、canonical、`hreflang`、Open Graph、结构化数据及页面首要内容。服务页使用 `Service`，诊断指南使用 `Article`，工具使用 `WebApplication`，并配有面包屑与组织资料。
- 未知路径由生成的 `_redirects` 返回真实 `404.html` 和 HTTP 404；私有应用路径继续使用受限 SPA 壳并保持不索引。非公开工具可直达时输出 `noindex,nofollow,noarchive`，不会进入站点地图。
- 每次内容或路由变动后，运行 `cd frontend && npm run build`，检查 `dist/sitemap.xml`、`dist/robots.txt`、`dist/404.html` 和受影响路径的 `dist/<path>/index.html`。不要手改构建产物。

### 1.2 双市场发布事实

- `.com` 前端从 `main` 发布到 Cloudflare Pages；共享 Worker 也只从 `main` 发布。
- `.cn` 前端、后台和工程师端的生产发布来自 `china-edition`，并必须手动运行 Aliyun ECS workflow。Cloudflare Pages 的中国版辅助部署不代表 `.cn` 已更新。
- 现有 Aliyun workflow 会打包构建产物、切换 `frontend`、`engineer`、`admin` 的当前版本并重载 nginx；它尚未包含技术基础计划中待授权的 nginx 公共路由改造。不得把该改造描述为已完成。

### 1.3 页面上线清单

每个候选公开页面均应满足：

```
□ 公开路由清单中的唯一路径、标题、描述和 canonical
□ 双语 alternate 链接与对应市场域名
□ 构建后的静态 HTML、结构化数据和真实 404 回归检查
□ 一个明确的搜索意图和一个对应的 CTA
□ 可追溯证据负责人；诊断内容还需通过发布证据门槛
□ 至少一个相关服务或工具内部链接，且不制造同义词重复页
□ 图片 alt、移动端可读性和安全/来源边界（如页面包含图片或技术建议）
```

## 二、关键词与内容策略

### 2.1 关键词分层

```
第一层：品牌词
  "SAGEMRO"、"SAGEMRO 技术服务团队"

第二层：服务意图
  "laser cutting machine repair"、"激光切割机维修"
  "press brake repair"、"折弯机维修"

第三层：可验证问题意图
  "laser protective lens burning"、"激光保护镜片频繁烧坏"
  "press brake angle inaccuracy"、"折弯角度不准"

第四层：工具与准备意图
  "metal weight calculator"、"材料重量计算器"
  "laser cutting cost calculator"、"激光切割成本计算器"
```

不要把上述示例解释为搜索量或排名承诺。查询和页面的完整分配、证据状态及优先级都在关键词映射中维护。

### 2.2 页面写作与去重

- 一个页面只服务一个主意图。标题、H1、首段、H2、图片 alt、描述和 URL 自然表达该意图，不用关键词密度指标驱动堆砌。
- 同义词、英美拼写或中文近义说法应成为同一页的辅助查询；它们不是新增页面的理由。
- 诊断内容先区分“观察到的现象”和“已完成的诊断”，显著说明安全停止/升级条件，并把有风险、无来源或未核实的记录留在草稿。
- 工具页必须让公式、示例、假设、局限和工程师复核边界与实际计算保持一致。没有充分证据的工具保持直达但禁止索引。

### 2.3 内容发布流程

1. 在关键词映射中确认服务相关性、独立意图、目标 CTA 和证据负责人。
2. 收集制造商、部件制造商、标准机构或获批内部证据；记录来源、访问日期和审核人。
3. 先在数据记录中完成双语内容与安全边界，再通过公开路由、静态产物和内部链接检查。
4. 只有 `published` 记录才可进入 manifest、站点地图和索引申请。草稿不是待抓取页面。

## 三、搜索平台与数据运营

### 3.1 Google Search Console（只读分析）

Search Console 是 Google 搜索表现的权威来源，当前在已审计的 28 天窗口内只有 **11 次展示**。这个样本不足以推断关键词量级或排名趋势，也不应用外部工具补造搜索量。

每周以只读方式导出或记录：日期范围、国家/市场、查询、页面、展示、点击、CTR、平均排名、覆盖/编入索引状态、抓取或软 404 问题。先核对公开 URL 的 HTTP 状态、canonical 和构建后 HTML；通过后才可请求索引。把提交 `https://sagemro.com/sitemap.xml` 和一个服务页、一个已发布指南的检查日期记录为 30 天对比基线。不要在代码中保存 Search Console 凭据。

### 3.2 百度搜索资源平台

百度是中文市场的独立搜索平台。需要站点所有者亲自登录；运营人员只能展示平台提供的**准确验证方式**。只有用户明确批准后，才可添加该次提供的验证文件或 meta token。不得猜测、复用 Google token 或自行变更验证方式。完成验证后提交 `https://sagemro.cn/sitemap.xml`，并按与 Google 相同字段记录基线、收录与抓取问题。

### 3.3 站内归因与看板

内部 Promotion Analytics 的“Acquisition / 自然搜索与 AI 引荐”标签只衡量到站后的汇总行为，不取代 Search Console 或百度数据。它使用 privacy-limited analytics v2，按页面和来源汇总，不展示原始访客身份。

来源名：

- `google_organic`、`baidu_organic`、`bing_organic`
- `chatgpt_referral`、`perplexity_referral`、`copilot_referral`
- 显式 UTM 优先；站内、空 referrer 和直接访问不进入该自然/AI 视图。

每周同时查看 Acquisition 看板的 landing sessions、engaged sessions、tool completions、CTA clicks、AI requests 和 service requests，并用页面/来源表与 Search Console 或百度的平台数据交叉解释。自然/AI 健康告警须至少有 20 个 session；低于该门槛标记为数据不足，不作为流量下降结论。

## 四、每周证据与 CTA 决策

每周固定执行以下规则，而非仅按展示量扩写内容：

1. 复核已发布页面的索引状态、搜索平台数据、归因行为和安全/证据变更。
2. 仅当候选主题同时具备**服务相关性、明确证据负责人、与现有页不同的搜索意图、明确目标 CTA**时，才可进入内容队列。
3. 如果查询只是现有页的同义词，合并到该页面的主查询或辅助查询；不要创建竞争同一意图的页面。
4. 若来源失效、风险边界不充分、内容与 CTA 不再匹配，或数据发现错误，将记录退回 `draft`；工具同时设为禁止索引。撤销索引并不等于删除直达功能。
5. 对高展示低 CTA 的已发布页面，优先检查意图是否错误、CTA 是否与页面任务一致、证据是否足够和内部链接是否正确；不要先添加泛化文案。

30/60/90 天复盘分别关注：收录/抓取与非品牌展示；查询/页面增长和自然/AI 到站行为；以及合格诊断或服务申请与后续扩写、合并、更新或退回草稿的决定。

## 五、站外与本地传播

### 5.1 外链建设

| 来源 | 做法 |
|------|------|
| 知乎回答 | 在与公开、已审核内容直接相关的回答中自然引用页面，不承诺维修结果。 |
| 行业论坛 | 用实务讨论和来源链接参与，不在不相关主题散布链接。 |
| 合作伙伴 | 仅与真实服务或设备合作关系页面互链，并保持链接目标可公开访问。 |
| 公众号/行业内容 | 在内容末尾链接到与读者任务匹配的服务页、已发布指南或可索引工具。 |

### 5.2 本地服务表达

区域服务页面或地图资料必须先由运营确认公司、服务范围和可证明的地址/联系人。不要从域名、备案或搜索平台要求推断服务覆盖范围；现场可用性始终以设备、地点、紧急程度和工程师匹配审核为准。
